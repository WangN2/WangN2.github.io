CEM 与 Diffusion

CEM 不关心动作长什么样，只关心哪条轨迹分数高；Diffusion 反过来。这不是替代关系，是分工关系。

2026-11-01约 6 分钟规划与生成全系列 ›

1. 这就是 CEM

交叉熵方法（Cross-Entropy Method）。名字来自它最初的推导——最小化两个分布之间的交叉熵，但在强化学习的这个版本里，实际做法更直白：采样一批，挑出最好的几个，再用这几个重新估计分布，重复几次。

它属于「估计分布算法（EDA）」这一族，区别于随机射击（random shooting）：随机射击只采一轮取最好，CEM 会用精英重新拟合一个分布，下一轮在更好的地方采。

这段实现常见于 MOPO、MBPO 这类基于模型的强化学习代码库，做的是模型预测控制（MPC）那一步。

2. 逐行拆开

class CEM:
    def __init__(self, n_sequence, elite_ratio, fake_env, upper_bound, lower_bound):
        self.n_sequence = n_sequence    # 每次采样多少条动作序列
        self.elite_ratio = elite_ratio  # 精英比例
        self.upper_bound = upper_bound  # 动作物理上限
        self.lower_bound = lower_bound  # 动作物理下限
        self.fake_env = fake_env        # 学出来的动力学模型

    def optimize(self, state, init_mean, init_var):
        mean, var = init_mean, init_var
        X = truncnorm(-2, 2, loc=np.zeros_like(mean), scale=np.ones_like(var))
        state = np.tile(state, (self.n_sequence, 1))

        for _ in range(5):
            lb_dist = mean - self.lower_bound
            ub_dist = self.upper_bound - mean
            constrained_var = np.minimum(
                np.minimum(np.square(lb_dist / 2), np.square(ub_dist / 2)), var)

            action_sequences = [X.rvs() for _ in range(self.n_sequence)] \
                               * np.sqrt(constrained_var) + mean

            returns = self.fake_env.propagate(state, action_sequences)[:, 0]

            elites = action_sequences[np.argsort(returns)][-int(self.elite_ratio * self.n_sequence):]

            new_mean = np.mean(elites, axis=0)
            new_var = np.var(elites, axis=0)
            mean = 0.1 * mean + 0.9 * new_mean
            var = 0.1 * var + 0.9 * new_var

        return mean

输入的形状

init_mean 和 init_var 不是两个数，而是一条轨迹的扁平化参数：规划十步、每步七个关节，就是七十维。所以「均值」其实是一个七十维向量，代表一条标的轨迹。

为什么用截断正态

truncnorm(-2, 2) 把采样限制在两个标准差以内。纯高斯会在尾部偶尔吐出极端值，而这些极端值扔进动力学模型里会得到毫无意义的结果，白占算力。截断掉，采样更集中在有意义的区域。

方差为什么被压缩

这段是整份代码里最不像算法、但最实际的一行：

constrained_var = np.minimum(
    np.minimum(np.square(lb_dist / 2), np.square(ub_dist / 2)), var)

因为采样被截断在 ±2σ，所以只要 σ ≤ (mean − lower)/2，那么 mean − 2σ 就仍然在下界之上。反过来，如果均值已经贴着边界，允许的方差就必须变小，否则一半的采样都落在界外。

这是「先约束分布，再采样」而不是「采样完再裁剪」。后者会把所有出界的点挤到边界上，形成一个人为的尖峰，分布会变形。

精英与平滑

排序取前 15%，用它们的均值和方差做下一轮的分布。但新参数不直接用，而是 0.1·旧 + 0.9·新。

这一步是经验性的：完全信任精英会让分布收缩太快，两三步就退化成一个点，后续再采样也没有探索能力；保留一点历史，相当于给收敛加了个阻尼。

3. 它到底有多强，也有多弱

先把一个常见误解纠正掉：CEM 不是「比梯度法更不容易陷入局部最优」。

它就是围绕当前均值做的局部搜索。均值在哪，它大概率就收敛到哪个峰。下面这个实验能直接看到：目标函数有两个峰，初始均值放在较小的那个附近，CEM 会老老实实收敛到近处的峰。

CEM 的收敛过程

蓝点是当前分布的均值，椭圆是 1σ 与 2σ。每步采样、择优、用精英重估分布。背景颜色是目标函数值，越深越高。

4. 亲缘：CEM 和 MPPI

说到采样规划，绕不开 MPPI（Model Predictive Path Integral）。两者都要采样、评估并更新控制分布，但不是只换最后一行：奖励如何变成权重、更新的是均值还是控制增量、是否更新协方差，都可能不同。

对比项本文的 CEM典型 MPPI
怎么用样本只取前 k 个精英重估均值与方差通常按指数权重使用全部样本
更新式mean ← 精英均值，并平滑更新方差常对名义控制序列叠加加权噪声增量
超参精英比例、方差与平滑系数温度 λ、噪声与步长等
典型倾向精英选择更离散，分布会随精英重估连续加权保留更多样本信息

CEM 的「只留前 k 个」对精英比例和样本数敏感；MPPI 的指数加权则对温度和奖励尺度敏感。谁更快、更平滑或更稳定，要结合具体更新规则和任务实测，不能只看这张表。

5. 为什么不求导

这里要分清楚：「不用梯度」不一定是技术上不能求，而是在模型误差、非平滑接触、长时展开或离散事件下，梯度未必可靠或划算。

动力学模型如果是神经网络，技术上可以求导，但沿多步展开后，梯度可能受模型偏差与数值病态影响。CEM 的容错性来自它直接使用整条轨迹的评分，不要求局部梯度方向准确；这不保证它找到全局最优。

代价也很清楚：用大量并行评估换取无梯度的搜索方式。每走一步都要推演许多未来轨迹，是否必须使用 GPU 取决于模型、样本数、规划时域和实时预算。

6. 和 Diffusion / Flow Matching 的四个维度

这两者的关系，用「谁在解什么问题」来看最清楚。

对比项CEMDiffusion / Flow Matching
解什么问题给定目标，找高奖励动作（优化）给定数据，拟合动作分布（生成）
知识从哪来来自当前的奖励函数与动力学模型，现场算主要来自训练数据，离线学
每一步做什么采样 → 打分 → 重估分布从噪声出发，按学习到的生成过程迭代
常见失效可能收敛到局部解或塌缩过早可能生成不合理、不满足约束或偏离数据分布的动作

所以它们在这类机器人系统里的位置不一样：CEM 是运行时的采样规划器，Diffusion / Flow Matching 可以提供训练出来的先验；生成模型也能参与在线优化，两者不是互斥类别。

一句话概括：CEM 是「按当前评分反复试错」，Diffusion 是「利用训练数据形成生成先验」。前者依赖模型和奖励且计算量大，后者依赖数据，也不自动保证约束或最优性。

7. 它们怎么结合

现在的主流做法不是二选一，而是把两者接起来。常见三种接法：

一、把 Diffusion 当采样器。原来 CEM 从高斯里随机撒点，改成从 Diffusion 里采一批「像人」的候选轨迹，再用奖励函数打分、选精英。这样同样 500 条样本，覆盖的都是合理动作，效率高得多。

二、把奖励当引导。在去噪的每一步加一个朝高奖励方向的修正（reward / classifier guidance）。这不是采样之后挑，而是让生成过程本身朝着目标偏。

三、生成后择优。模型生成十条，用物理引擎或奖励模型算一下分，挑最好的执行。最简单，也最贵。

三种做法可以叠加。真正决定效果的不是选哪种，而是奖励函数写得对不对——如果奖励本身不能反映任务成败，再好的生成器也只是在错误的目标上跑得更快。

8. 收尾

这段 CEM 代码之所以值得读，是因为它把「规划」拆成了三个可检查的动作：采样、打分、重估。三个动作各自都能替换——采样换成 Diffusion，打分换成学出来的奖励模型，重估换成 MPPI 的加权——但骨架不变。

所以看待新论文时，可以先问一句：它换的是这三个动作里的哪一个？换完有没有解决原来那个动作的瓶颈？
