NOTE 06 / 移动底盘 · 运动学

全向底盘：
四个舵轮怎么同时听话

舵轮的逆运动学只有三行公式。真正让它在实机上跑起来的，是另外三件事：每个角都有一堆等价写法、轮子可以反着转、以及转向机构有硬限位。

2026-10-23约 6 分钟移动底盘

前面的笔记都在讲上半身和视觉。这一篇补上底盘：一台人形机器人站在四个舵轮上，凭什么能横着走、还能原地转。内容对应站内 G2 实验室里「控制部位 → 全向底盘」那一组控件；把读数表和本文的公式对一遍，就知道那些数字是怎么来的。

范围。本文只讲理想无滑移的运动学映射：给定底盘速度指令，算出四个模块各自该转到哪、转多快。不涉及轮胎打滑、地面摩擦、电机动力学，也不涉及定位。

1. 为什么用四个舵轮

移动底盘有三条常见路线，差别在于「能不能横着走」：

方案自由度代价
差速（两轮 + 万向轮）前后 + 转向，不能横移结构最简单，但窄通道掉头很费劲
麦克纳姆轮全向，可斜行靠辊子侧向分力，效率低、振动大、对地面敏感
四个舵轮全向，轮子始终纯滚动每个模块多一套转向电机和编码器，控制变复杂

舵轮贵在机构，赢在效率：每个轮子的朝向都可以主动对准运动方向，所以轮胎始终是纯滚动，没有侧滑损失。代价是每个模块都多了一个要解的量——转向角。

2. 每个模块只负责自己那一点速度

刚体上任意一点的速度，等于「质心平动」加上「绕质心转动的切向速度」：

v_i = v + ω × r_i

写成平面分量，设模块位置为 (x_i, y_i)、底盘指令为 (vx, vy, ω)：

v_ix = vx − ω · y_i
v_iy = vy + ω · x_i

这就是全部。四个模块互不知道对方在干什么，各自把属于自己那一点速度走出来，整台底盘的运动就对了。这条「局部正确 ⇒ 全局正确」的性质，是舵轮控制代码能写得这么短的原因。

3. 从模块线速度到轮速

模块速度是一个二维矢量，舵轮只有两个执行量：转向角和滚动角速度。所以先取方向，再取大小：

θ_i = atan2(v_iy, v_ix)　　# 转向角
s_i = |v_i| / r　　　　　　 # 轮速（rad/s），r = 0.07 m

以本机参数为例：模块位于 (±0.23, ±0.218) m，轮半径 0.07 m。指令「沿 +X 前进 0.2 m/s」时，四个模块的转角都是 0°，轮速都是 0.2 / 0.07 ≈ 2.857 rad/s。

指令「原地以 0.3 rad/s 右转」时，四个模块的线速度方向各不相同，转角也不再是整齐的 0 / 90 / 180：

模块位置 (m)转向角轮速 (rad/s)
(0.23, 0.218)−46.5°−1.358
(−0.23, 0.218)+46.5°−1.358
(0.23, −0.218)+46.5°+1.358
(−0.23, −0.218)−46.5°+1.358

注意右上角那个模块：按公式它是 atan2(0.069, −0.065) ≈ +133.5°，但表里写的是 −46.5°——正好差 180°，轮速也取了负。这不是笔误，是下一节的内容。

5. 每个角都有一堆等价写法

轮子是用来滚的，不是用来指的。同一个速度矢量，可以用两种方式实现：

(θ, s) 与 (θ + 180°, −s) 等价

指向反方向、倒着转，效果完全一样。这一步把「转角」的可行集合从一条射线变成了一条直线，于是每段都能挑一个离当前角度最近的解——这就是就近转向。

再看第 3 节那张表：右上模块本来该转到 +133.5°，但它的当前角度是 0°，转到 +133.5° 要转 133.5°；改成 −46.5° 加反转，只要转 46.5°。三个模块的转向时间因此大幅缩短，而底盘的运动会分毫不差。

还有一层：等价角不只两个。因为转角是周期量，θ、θ±360° 描述同一个物理朝向，所以候选集合是 θ + k·180°（k 取整数）——奇数 k 对应反转，偶数 k 对应正转。实现里通常只需要在 k ∈ [−2, 2] 里找。

把上面那个按钮切到「不许反转」，再给一个接近 −X 方向的指令：你会看到模块被顶在限位上出不来。这说明一件事——反转不是优化技巧，而是全向运动能在有限转角内成立的必要条件。

6. 转向限位与零速保角

真实模块的转向盘不能无限转：线束会拧断、限位开关会撞。本机的限制是 ±2.97 rad（约 ±170°），略小于 ±180°。这个「略小于」很关键：

  • 因为不到 180°，正前方和正后方之间没有直通路径，必须靠反转绕过；
  • 如果指令方向正好在 ±180° 附近，正转候选会被限位筛掉，只剩反转候选；
  • 所以候选筛选必须在「挑最近的」之前做——先删掉越界的，再排序。顺序反了，就会挑出一个转不过去的角。

另一个容易被忽略的边界是零速。速度为零时，atan2(0, 0) 没有意义，模块应该保持上一次的角度，而不是回零。回零会让底盘在每次停车时都抖一下，而且下一次起步要重新转过去，白白多花时间。

7. 为什么必须「先转向、再滚动」

理论上转角与轮速可以同时给，但实机上不行：轮子一旦滚起来，再让转向盘去拧它，就变成了带着侧向载荷转向——轮胎在旁边擦地，编码器读数也跟着乱。所以控制顺序是：先把四个模块转到目标角、确认到位，再给轮速。

这条约束反过来影响上游：如果每一段都要停下来转向，那路径规划就该尽量少切换方向；反过来，如果底盘要连续走一条曲线，模块的转角就得连续跟随曲线的切线方向，而不是近似成几段直线。

8. 验收该看什么

这套代码最容易写错的地方，恰恰也是最容易「看起来对」的地方。有三条经验：

  • 验收条件写模块速度矢量，不要写转角。等价角有无数个，「轮子朝哪边」不是对错的标准；把 s·cosθ 和 s·sinθ 还原成模块线速度，再去和 v + ω×r 比，才是。
  • 用三个典型指令做回归：纯前进、纯横移、纯自转。它们分别覆盖「同向」「同向反号」「切向」三种模式，任何一个错了都会立刻暴露。
  • 不要断言具体角度。两个候选一样近时，选哪个取决于遍历顺序——实现细节不该被写进验收条件，否则重构一次就红一片。

站内的 G2 实验室用的就是这套判定：给定底盘指令后，把四个模块的「转角 × 轮速」还原成速度，再和期望值逐项比对，误差要在 1e-10 量级内。这也解释了为什么那段代码里一个角度常量都没出现。
