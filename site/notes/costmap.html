1. 为什么机器人不能当点看

二值占用栅格把世界分成两类：有障碍、没障碍。规划器如果直接在这张图上找最短路，结果会很诚实——贴着障碍走。因为贴着走确实最短。

问题在于机器人不是一个点。它的外轮廓会扫过一个区域，而这个区域在任何一张栅格图上都只是一个点。于是「路径合法」和「机器人能通过」变成了两件事。

代价地图的做法是把这件事变成一个连续量：每个格子除了「有没有障碍」，还带一个 0–254 的代价，表示「离障碍多近、有多不想待在这是」。规划器于是有了偏好：能绕就绕，绕不开才贴着走。

2. 一个格子的四种身份

状态取值范围含义
自由 free0远离一切障碍，代价为零
膨胀 inflated1 – 252离障碍还有距离，代价随距离衰减；可以通过，但要付出代价
内切 inscribed253离障碍近到机器人内切圆已经压上；中心不该出现在这里
致命 lethal254障碍本身

这四个数不是随便分的：253 和 254 是两个阈值，252 是「有代价但还有救」。规划器只用后两个数做硬判断，其余全靠代价算总账。

3. 膨胀：把距离变成代价

膨胀层对每个格子算它到最近障碍的距离 d，再套一条衰减曲线。实现里常见的形式是：

cost = 253 · exp( −k · (d − r_in) )　　（r_in < d ≤ r_infl）
d ≤ r_in → 253　　d ≤ 0 → 254　　其他 → 0

其中 r_in 是内切半径、r_infl 是膨胀半径、k 控制衰减快慢。用指数而不是线性，是因为离得越近，代价该涨得越急——贴着墙的一格和离墙 5 cm 的一格，危险程度差得远，但和离墙 50 cm 与 55 cm 之间几乎没差别。

下面的实验把这张图直接画出来。三个滑块分别控制内切半径、膨胀半径和衰减，拖动蓝色圆点看它落在哪一层。

膨胀与代价值

拖动蓝色圆圈（机器人内切圆）移动到不同位置，右侧读数会给出该格的代价与判定。红褐色环是内切区，中心落在那里就该判碰撞；再外面是渐变，越蓝代价越高。

4. 膨胀半径不是安全余量

最常见的误解是「膨胀半径 = 机器人半径 + 安全余量」。这句话对圆形机器人成立，对真实机器人不成立。

你以为实际
机器人是个圆，半径固定多数是矩形或 L 形 footprint，不同朝向的内切圆半径不同
膨胀半径就是一个安全边距它定义的是「代价从 253 衰减到 0 的范围」，是偏好场的宽度，不等于物理间隙
半径调大一点更安全调太大，窄通道直接被判死，机器人原地不动；调太小，贴着墙走

真正的硬约束是内切半径：中心进到这个范围，外轮廓必然已经压上。膨胀半径只影响「愿不愿意靠近」，不影响「能不能靠近」。

还有一个隐含假设：膨胀是在当前朝向下算的。如果规划器允许原地转向，那同一位置不同朝向的内切圆并不一样，用单一半径只能取保守值——这不是错误，是建模代价。

5. 二维地图上的三维机器人

碰撞包络那篇里的 22 个球是三维的：手臂举高、头身前倾，球心的 z 都不一样。代价地图是二维的：所有东西投影到地面。

投影会丢信息。最典型的两件事：

  • 高处的障碍看不见。横在半空的线缆、悬空的工装，在二维地图上要么不存在，要么被错误地当成地面障碍。前者导致撞，后者导致明明能过却不敢过。
  • 高处的自己也不存在。手臂伸出去的那一截不进 footprint，地图上那一块仍是「自由空间」。机器人可能举着胳膊穿过一个它其实过不去的门洞。

所以「碰撞球」和「costmap 膨胀」是两套东西，各管一层：前者描述三维几何，后者描述二维通行性。只做一套，另一边一定有洞。

6. 代价不是约束

代价地图给的是偏好，不是禁令。规划器算的是总代价最小——如果绕路要多走 20 米，它完全可能选择穿过一片代价 200 的区域。

这带来一个验收上的差别：不要只看路径长度和是否到达，要看路径上的最大代价。一条平均代价很低、但有一小段冲进 253 区域的路径，仍然是失败的。

更隐蔽的是时效性。代价地图是滚动刷新的，如果障碍层停止更新，地图会一直显示旧世界——规划器照样给出「合理」的路径，只是那条路已经不通了。代价地图要有时间戳，规划前要检查它够不够新。

7. 调试时先看什么

  1. footprint 对不对。把机器人开到墙边，看内切圆是不是刚好贴住。对不上，先修 URDF 或参数，别去调膨胀。
  2. 内切半径与膨胀半径的关系。膨胀必须不小于内切，否则中间会出现「无代价但会撞」的缝隙——图上表现为障碍周围一圈白。
  3. 滚动窗口边界。局部代价地图只覆盖机器人周围一小块；规划出界时，路径会在边界上「凭空拐弯」。
  4. 时间戳与坐标系。代价地图挂在哪个 frame、多久更新一次，比调参数重要得多。
