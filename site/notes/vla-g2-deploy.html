NOTE 10 / 具身模型 · 环内与环外

把大模型
放在闭环外面

大家都想把大模型放进控制环里，让它看画面、出动作。可控制环要的三样东西——低延迟、错误可逆、能拿到本体感受——恰好是它最弱的三条。这篇文章想说的是：它该站在环外，而且环外有三个位置，比它现在待的地方值钱得多。

2026-10-28约 12 分钟具身模型全系列 ›

这一篇是一次判断，不是一个结果。它不报告成绩——微调仍在进行、真机尚未接入、模型生成专家也还没开始跑。它要说的是：大模型该站在具身闭环的哪一侧，以及为什么现在几乎所有人，都挤在错的那一侧。

范围。本文是一次方法判断，基于仿真闭环的实现经验展开，不含真机部署结论。文中数字都来自已实施的部分，计划的用「计划」「目标」「判定」标注，不混进结果里。

1. 一次迁移到底贵在哪

把现在这条流水线摊开，标出「换任务时哪些要重来」：

环节现在怎么做的换任务 / 换机器人
资产导入URDF → 仿真模型，修惯量、理碰撞换机器人要重做一次
专家脚本六阶段策略 + 逆解 + 容差 + 异常分支每个新任务都要重写
采集200 回合，自动跑自动，但要重扫随机范围
转换与微调字段映射、归一化、训练配置改配置，不重写逻辑
评测固定种子 + 机械判据判据要跟着任务改

算力和采集时长都不是主要成本——那些是机器的时间。真正压在人身上的是「每换一个任务，就重写一版专家」：读懂新的接触几何、设计阶段顺序、调容差、处理异常、跑通采集。

这也解释了为什么这条路线扩展得慢。资产导入是一次性投入，微调是配置问题，只有专家脚本是线性增长的人工投入——任务越多，欠的债越多。

2. 换个问法：环内还是环外

默认的思路是让模型进环内当策略：看画面、出动作、闭环控制。这个位置对模型的要求是三条——低延迟、错误可逆、能拿到本体感受。

而这恰好是它最弱的三条：

要求控制环的实际情况大模型的现实
延迟控制周期 8–10 ms本地推理已是数百毫秒；云侧一次往返 300 ms 起
错误可逆性撞了就是撞了幻觉无法回滚，也没有「撤销」
上下文力、电流、编码器，都是高频低语义信号它只看得见你喂进去的 token

所以真正该问的不是「大模型能干什么」——它能干的太多了。该问的是：哪些环节延迟不重要、错了能发现、而且本质上是符号处理？

答案是闭环外面那一圈。而那一圈，恰好是具身智能现在最贵、也最少人做好的部分。

三条判据

判断某个位置该不该放模型，只看三条：

  • 延迟容忍：一分钟出结果可不可以？
  • 错误可检出：它错了，我能不能靠跑一遍发现？
  • 上下文是否充足：它要的信息，能不能真的放进输入里？

第二条是分水岭。模型可以用在「错了能便宜地发现」的地方，绝不能用「错了不可逆」的地方。这条比模型强弱重要得多。

八个位置，按三条判据排

位置延迟错误可检出上下文判断
实时策略✗✗✗最差位置，却是现在最挤的地方
在线重规划△ 秒级△✗ 看不见力谨慎
任务规格（阶段 / 约束 / 判据）✓✓✓好
示范生成（写专家）✓✓✓好
验收器编写✓✓✓最好
数据筛选与多样性检查✓ 分钟级✓✓好
失败归因✓ 分钟级△✓好
课程设计（下一步采什么）✓ 小时级△✓可试

把「实时策略」和「验收器」放一起看：前者延迟要求最高、错了不可逆、还拿不到关键信号；后者没有延迟要求、错了跑一遍就知道、需要的上下文全在任务描述里。同样是「把大模型用在具身上」，两者的期望值差了一到两个数量级。

3. 三个必须掰开的概念

在讨论「谁来当专家」之前，先固定三个说法，否则后面每句话都有歧义。

看起来一样实际是两件事
「专家」程序专家：用真值坐标和逆解生成示范轨迹的程序，产出训练数据。
动作专家：VLA 网络内部负责生成动作的模块，是被训练的对象。两者除了中文名没有任何关系。
「微调前」官方原始权重：没在这台机器人上做过梯度更新。
严格零样本：连字段映射、归一化、相机视角都不改。本项目属于前者——已做完整适配，所以叫「本协议下的基线」。
「198/200」示范合格率：采出来的回合里，多少条通过了数据完整性检查。
模型成功率：模型在独立种子上跑出来的。两者可以差到 198 比 0。

这三个区分在本文里反复用到。尤其是第一个：我们想替换的是「程序专家」，不是「动作专家」——后者才是被训练的那个。

4. 但先别急着换老师

公开权重在这台机器人上的成绩是验证 0/10、独立测试 0/20。看到这个数字，最常见的两种解读是：

  • 「模型不行，得换个更强的」；
  • 「模型还没学会，得多训」。

这两种解读指向完全相反的动作，而现在还分不出来。所以第一件事不是换老师，是把「卡在哪」测出来。

在这个量级上，0/20 说明不了「模型学不会」——它只说明「还没开始学」。要判断卡在哪，至少要三条对照：

这三条在评测之前就该排好。先证明任务可解，再评模型；先看单步误差，再谈闭环。顺序反了，会把「映射错了」误判成「模型没学会」，然后去调一堆不该调的参数——包括换一个更贵的老师。

5. 环内的位置，为什么现在不行

以 GPT-6-Astra 这类通用多模态策略为例。它是目前最接近「通用策略」的形态：把专家示范总结成任务指导与接触参考，结合多模态观测与交互历史生成指令，靠接触反馈做纠正；不做机器人专用预训练，也不做逐任务微调。

即便如此，把它放进这个闭环，仍然会撞三堵墙：

墙具体表现后果
延迟单次推理约 0.79 秒，而一个动作块只覆盖 0.4 秒闭环在等待里空转，测出来的「成功率」和实时跑的不是同一个数
不可逆控制指令错了就是撞、是摔、是伤没有回滚余地的位置，不应该交给会犯错的组件
缺关键信号当前观测是三路 RGB 加关节状态，没有力或触觉这类模型最值钱的能力（接触反馈纠错）在现在的配置里拿不到

三堵墙里没有一条是「模型再强一点就能解决」的。延迟是部署形态问题，不可逆是物理问题，缺信号是传感器问题。把更强的模型塞进环内，是在用它的短板去拼别人的专项。

还有一个常被忽略的事实：这类模型仍然需要示范——只是把示范压成上下文，不做梯度更新。它省的是训练，不是数据。所以在「谁来产出示范」这个问题上，它并没有替代什么，只是换了个消费者。

6. 环外的四个工位

把「环内」划掉之后，剩下四个位置，按我目前的判断，价值从低到高是：规格 → 示范 → 归因 → 验收器。

工位一：任务规格编译器

现在「任务」是写死在专家脚本里的：六个阶段、每个阶段多少步、容差多少。人改了脚本，任务就跟着变，没有任何地方记录「这次任务到底要求什么」。

输入：一句任务描述 + 场景约束 + 机器人能力清单
输出：阶段序列 · 每阶段进入与退出条件 · 随机化范围 · 成功判据

让模型做的不是写代码，是写规格——一个介于自然语言和程序之间的中间产物。它有三条好处：可被机器检查（阶段覆盖是否完整）、可被复用（换机器人只改能力清单）、可被对照（这次和上次的任务定义差在哪）。

失败模式：模型会把规格写得比实际能做到的更理想，比如「先观察再决定」。落到执行器时没有对应原语，整条链就断了。所以要加一条硬约束：规格里的每个原语，必须能在执行器里找到实现。

工位二：示范生成器

这里要换一个说法，才说得清它为什么安全：

模型不需要「会做这个动作」，只需要「能描述这个动作」，
再由确定性求解器去执行这个描述。

这一步把「控制」换成了「描述」。描述错了，逆解会失败、轨迹会越界、预检会拒绝——错了能立刻发现，这就是它比直接控制安全的原因。

失败模式：描述出来的动作在几何上合法、在物理上不可行——穿模、超出关节限位、和桌面干涉。所以描述必须过一遍物理预检才能执行，不能直接下发给仿真。

判断这条路走没走通，看四个数：开发时间（从任务描述到首个通过验收的回合，人时）、生成有效率（通过机械验收的回合占比，对照程序专家的 198/200）、多样性（轨迹簇数与阶段时长分布）、下游效果（用这份数据训一版，在同一种子上评测）。

判定线先写死，免得事后找理由：有效率低于 90% 说明脚本还不可用；开发时间缩短不到一半说明成本优势不成立；下游明显不如基线说明脚本覆盖不到关键状态——那是要加约束，不是加数据。

工位三：失败归因器

现在的做法是跑 20 回合、看到 0/20，然后靠人猜。模型在这个位置的价值不是给答案，是给一张假设表加每条的证伪方法：

输入：回合轨迹、接触记录、动作块与实际执行的偏差
输出：分层假设（数据对齐 / 映射 / 输出分布 / 视觉 / 时序）+ 每条的判别实验

判断它有没有用的标准很硬：它给出的每个假设，都要能对应一个两小时内跑完的实验。做不到就是空谈。

失败模式：模型会倾向于给出「听起来合理但无法证伪」的解释，比如「可能是视觉分布不匹配」。好的归因必须落到可测量的量上——某一路相机在训练集和测试集上的像素分布差了多少。

工位四：验收器编写

这是我认为最值钱的一个，下一节单独说。

7. 为什么「验收器」是杠杆点

大家想的是「让模型生成数据」。但数据对不对，取决于验收器。验收器是整个系统里唯一的杠杆点，因为它一次写好，同时解锁三件事：

验收器写好 → 能自动筛掉坏数据 → 才敢用模型生成数据
　　　　　→ 多来源数据可混用（人工 / 程序 / 模型三类专家）
　　　　　→ 有判据才说清怎么失败的 → 失败归因才有意义

还有两个被低估的属性：

  • 它是代码。而代码是大模型最强的模态，比让它输出动作强一个数量级。它可读、可审计、可版本化、可跑单测。
  • 它是可复用的资产。换任务时专家脚本要重写，验收器的骨架（接触、行程、保持时间、无深接触、步数上限）基本不变。

具体让它做什么：

输入：任务判据约定（接触事件、行程百分比、保持时长、深接触阈值、步数上限）
输出：可执行的判定函数 + 一组「应该被判失败」的负样本

注意后半句。一个只会判成功的验收器没有价值，必须能证明它也会拒绝。

8. 必须设防：自证闭环

这条路走到深处会撞上一个陷阱：

模型写专家 → 模型写验收器 → 模型判成功

三个环节都在模型手里，等于自己出题、自己答题、自己判卷。这时候「成功率 95%」可能只是「验收器写得很宽松」。这不是假想——判据写成什么样，结果就能是什么样。

三条防线，缺一不可：

防线做法为什么有效
判据锚在物理量上接触事件、行程百分比、时间、是否穿模——全部来自仿真器，不来自语言模型物理量不能被措辞放松
负样本测试拿一批已知失败的轨迹喂进去，必须判失败；这批样本由人准备外部锚，破了自证循环
交叉验证程序专家的验收器与模型写的验收器，在同一批数据上结论要一致不一致的地方就是分歧点，必须解释

这三条里最重要的是第二条。验收器本身也要被验收，而验收它的东西不能来自同一双手。

9. 现有的链路，与真机迁移

上面讨论的都是「数据从哪来」。数据往下走的链路已经跑通，这里只列关键约束。

自有资产 → 仿真环境 → 专家示范 → 数据适配与微调 → 独立评测
层最容易被忽略的细节
资产外观网格、碰撞几何、控制参数是三套东西；碰撞用凸包代理，不等于真实接触面
环境成功判定必须在环境侧独立执行，不能让被测模型自己判
示范专家读真值坐标，模型读图像——两者信息不对等，这个差距会一直存在
适配训练与推理的归一化统计必须同源；关节顺序和夹爪语义最容易错
评测检查点要预先锁定，一旦允许按分数挑，独立测试集立刻变成验证集

迁移到真机时，能带走的和必须重做的要分清：

能带走必须重做
模型权重与推理服务相机内外参、曝光、端到端延迟
字段映射与任务语言仿真位置伺服 → 真机控制模式，外加限速、限位、超时、急停
评测方法论成功判据本身——行程阈值是仿真弹簧的参数，换个按钮就不成立

最后一行最容易被漏：判据不是常量，它得跟着硬件一起迁移。

10. 这一篇的位置

前九篇讲的是推导与测量：运动学可以算对，示教站位只能测对。这一篇讲的是成本：模型本身越来越便宜，贵的是把它接到一台新机器人、一个新任务上的那部分工程。

所以真正的加速不在模型侧，在数据生成侧。而数据生成侧要提速，前提是有一套能自动判对错的验收器——这又回到了这个系列一直在说的事：模型负责把问题变小，测量负责给出可信的数。
