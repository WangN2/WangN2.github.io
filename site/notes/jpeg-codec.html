NOTE 11 / 视觉管线 · 编码与解码

编码是
传感器的口音

相机交给你的不是像素，是压缩过的像素。中间丢掉的那部分，模型再也拿不回来。

这一篇补一个最基础、却最容易被跳过的环节。前面几篇一直在处理「相机看到了什么」，但没人问过：相机交给模型的那张图，还是它看到的那张吗。

范围。讲 JPEG 这类有损压缩在机器人视觉链路里的位置与代价。不涉及视频编码（H.264/H.265），也不涉及 ISP 内部的白平衡、去噪、锐化——那是另一篇的事。

1. 先从一笔带宽账开始

传感器出来的是像素。但这条线传不动像素。

算一下：一台 1280×720 的相机，30 帧，每个像素 3 个字节。

一秒就是 82.9 MB。换成速率是 663 Mbps。

而接口是这样的：USB 3.0 实际能跑 350 MB/s 左右，GigE 只有 125 MB/s，USB 2.0 只有 35 MB/s。

USB 2.0 接一路 720p 原始图都做不到。GigE 勉强两路。

所以「相机输出 JPEG」不是谁的设计偏好，是物理逼出来的。传感器出 RAW，ISP 转成 RGB，紧接着就有一颗编码芯片把它压成 MJPEG 或 H.264——通常就在相机机身里。

编码是为了传得动。解码是为了算得了。中间那一步损失，就是这条线的过路费。

2. 编码做了什么

以 JPEG 为例，压缩分五步走。

第一步，色彩转换。RGB 变成 YCbCr：一个亮度通道，两个色度通道。为什么要转？因为人眼对亮度敏感、对颜色迟钝。把信息集中到 Y 上，剩下两个就可以放心砍。

第二步，色度下采样。常见的 4:2:0 把 Cb 和 Cr 的宽高各缩一半——色度信息直接丢掉四分之三。

第三步，切成 8×8 的块，每块做离散余弦变换。图像从「像素值」变成「空间频率系数」：低频描述大片色块，高频描述边缘和纹理。

第四步，量化。每个系数除以量化表里对应的数，取整。高频的除数是很大的，除完基本都是零。这一步是全流程唯一不可逆的地方。

第五步，熵编码。把这一堆系数用 Huffman 压成比特流。这一步是无损的，它只是把前面已经很稀疏的数据排得更紧凑。

「质量因子」这个词听起来像是在调画质，其实它调的就是第四步那张量化表乘多少。因子低，除数大，高频归零得多，文件就小。

4. 解码是逆运算，但逆不回来

解码走的是原路返回：熵解码、反量化、反余弦变换、色度上采样、YCbCr 转回 RGB。

问题出在「反量化」这三个字上。它并不是把丢掉的东西恢复回来，它只是把零乘回原来的除数，得到的还是零。

所以「编码一次、解码一次」，等价于对原图做了一次不可逆的低通滤波。解码器再贵、写得再好，也变不回原图。

这也解释了一个常见的困惑：同样的图，用 nvJPEG 和 libjpeg-turbo 解出来，像素值不完全一样。不是谁错了，是两者的反余弦变换实现和上采样插值不同。它们都对，只是浮点路径不同。

5. 三个参数，决定损失了什么

调参的时候，值得知道每个旋钮对应哪种损失。

色度采样。4:4:4 不采样，4:2:2 横向减半，4:2:0 双向减半。4:2:0 最隐蔽：它不降亮度分辨率，肉眼看不太出来，但颜色边缘已经糊了。对机器人来说这很要命——红橙难分、标签边界的颜色跳变变钝，而这些恰恰是视觉定位依赖的东西。

质量因子。它控制量化强度。低到一定程度，8×8 的块边界会变得肉眼可见，叫块效应。

色度质量。很多编码器允许亮度和色度分开设，色度设得低，就会出现大面积的颜色渗色。

如果要给一个经验值：做视觉定位和检测，色度别低于 4:2:2；做别的、只是给人看的监控画面，4:2:0 随便用。

6. 在你这条链路上，它们分别在哪

把整条链路摊开，编码和解码的位置很清楚。

光 → 传感器 → ISP（白平衡 / 去噪 / 锐化）→ RGB
　　　　↓
　【编码】JPEG / H.264　←　相机内部，你看不见
　　　　↓
　　USB / GigE / MIPI 传输
　　　　↓
　【解码】libjpeg / nvJPEG　←　主机侧，你能选
　　　　↓
　像素数组 → 模型

编码发生在相机里，你基本管不着，除非能改相机的曝光、压缩率这些参数。解码发生在主机上，这是你能选的：libjpeg-turbo、nvJPEG、DALI、OpenCV，差别只在速度和内存落点。

这里有个容易混淆的地方。很多人以为换一个更快的解码器，图像质量会变好。不会。解码器只决定「多快解出来、解到哪」，不决定「解出来是什么」。内容在上游编码那一刻就定死了。

顺带说一句选型：小图、单张、低帧率，CPU 解码通常比 GPU 快——因为 GPU 每次都有调度和传输的固定开销。真正该上 GPU 解码的，是高清大图、大批量，或者解码结果立刻要在显存里做推理的场景。

7. 一件容易被忽略的事：仿真里没有编码

这条链路在仿真里是断的。

仿真里是：渲染出无损的 RGB，直接喂给模型。

真机上是：光进传感器，过 ISP，被编码器压一遍，经线缆传过来，再解压，才到模型手上。

中间多出来的不只是压缩。还有白平衡、去噪、锐化，以及量化表留下的痕迹。模型在仿真里学到的纹理，是数学上精确的；真机上它看到的，是带着口音的一版。

这件事在排查「模型为什么在真机上不行」的时候，值得单独列一条：训练数据和部署数据之间，隔着一个编码器。

好消息是它很便宜就能补上。训练时对图像做随机 JPEG 压缩，质量因子随机取一段区间，就是仿真侧复现真机压缩伪影的标准做法。代价几乎为零，收益是模型不再把块效应当成异常特征。

这类随机化在数据增强里很常见，只是大家通常想不起它为什么有用——它补的不是「更多数据」，是一个被忽略的分布差异。

8. 收尾

编码是传感器的口音。你能听懂它，但它已经不是你说话的样子了。

解码器只负责让你听懂，不负责把口音去掉。

要去掉口音，只有两条路：要么把编码质量调高，让口音轻到听不出来；要么，在训练的时候就让它听带口音的话。
