机器人数据格式全景

URDF 描述身体，USD 组织场景，rosbag 保存运行过程，训练数据集整理可学习的经验。它们不是竞品，而是同一条数据链上的不同容器。

2026-11-08约 9 分钟数据基础全系列 ›

新手最容易把不同抽象层次的数据当成一回事：一个 .usd 文件里有机器人，不等于它就是 URDF 的替代品；一个 rosbag 里有图像和动作，也不等于它已经能直接训练 VLA。先分清每份数据回答什么问题，格式选择就会简单很多。

范围。这是一张工程地图，不是完整 API 手册。示例用于解释结构；LeRobot 等项目的目录和 API 会随版本变化，实际使用时应固定版本并对照对应文档。

1. 一张地图：四类数据，四个问题

层次回答的问题常见格式或协议典型生态
本体结构机器人由哪些连杆和关节组成？URDF / Xacro、MJCF、SDFROS、MuJoCo、Gazebo
场景与资产机器人、工装、灯光和物理环境怎样组织？USD / USDZ、网格、点云、地图Omniverse、Isaac Sim、导航与重建工具
运行记录每个时刻看到了什么、状态是什么、执行了什么？ROS 2 消息、rosbag2、MCAPROS 2、日志回放与排障
训练数据集怎样把示范整理成可采样、可对齐的序列？LeRobot、RLDS、HDF5 等模仿学习、VLA、离线强化学习

这是一种帮助理解的分层，不意味着所有数据都只能落在四类里。地图、标定参数和模型权重也有各自的生命周期；真正重要的是不要把结构、场景、日志和训练样本混成同一个抽象层。

2. URDF：机器人的结构说明书

URDF（Unified Robot Description Format）用 XML 描述机器人的 link 与 joint。它回答的是：有哪些刚体、刚体怎样连接、关节绕哪根轴运动，以及外观、碰撞和惯量如何表示。

<robot name="mini_arm">
  <link name="base_link">
    <visual>
      <origin xyz="0 0 0.025"/>
      <geometry><box size="0.1 0.1 0.05"/></geometry>
      <material name="gray"><color rgba="0.5 0.5 0.5 1"/></material>
    </visual>
    <collision>
      <geometry><box size="0.1 0.1 0.05"/></geometry>
    </collision>
    <inertial>
      <mass value="1.0"/>
      <inertia ixx="0.001" ixy="0" ixz="0"
               iyy="0.001" iyz="0" izz="0.001"/>
    </inertial>
  </link>

  <link name="upper_arm">
    <visual>
      <geometry><cylinder radius="0.025" length="0.3"/></geometry>
    </visual>
  </link>

  <joint name="shoulder_joint" type="revolute">
    <parent link="base_link"/>
    <child link="upper_arm"/>
    <origin xyz="0 0 0.05" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
    <limit lower="-2.96" upper="2.96" effort="20" velocity="3.0"/>
  </joint>
</robot>

同一个 link 可以有三套面向不同用途的描述：

标签服务对象内容
<visual>显示与渲染几何、网格、颜色和基础材质
<collision>碰撞检查通常比外观更简化的几何；它与 visual 不需要相同
<inertial>动力学质量、惯性原点与惯性张量；错误参数会污染动力学仿真

关节常见类型包括 revolute（有限位旋转）、continuous（连续旋转）、prismatic（平移）、fixed（固定）、floating（自由浮动）和 planar（平面运动）。选型不是背名词，而是明确自由度、轴向、原点与限位。

实际项目常用 Xacro 参数化生成 URDF，避免重复 XML。可用 check_urdf robot.urdf 检查结构，用 RViz 或 PyBullet 等工具加载验证。

边界。标准 URDF 主要表达单根运动学树，不能直接表达闭链机构；它有基础视觉和物理字段，但不擅长多资产场景、复杂材质、灯光与时间采样。需要这些能力时，才会进入 MJCF、SDF 或 USD 等更适合的表示。

3. USD：把机器人放进整个场景

USD（Universal Scene Description）最初面向影视与视觉特效生产，如今也是 Omniverse / Isaac Sim 的核心场景技术。它不只是文件后缀，而是一套用于构建、组合和读取三维场景的平台：机器人、料盘、相机、灯光、物理属性和动画都可以进入同一个 Stage。

#usda 1.0
(
    defaultPrim = "World"
    upAxis = "Z"
    metersPerUnit = 1
)

def Xform "World"
{
    def Xform "G2_Robot" (
        prepend references = @./assets/g2_robot.usd@
    )
    {
        double3 xformOp:translate = (0.5, 0, 0)
        uniform token[] xformOpOrder = ["xformOp:translate"]
    }

    def Cylinder "Tray"
    {
        double radius = 0.3
        double height = 0.02
        float physics:mass = 2.0
        bool physics:collisionEnabled = true
    }

    def DistantLight "Sun" { float inputs:intensity = 1000 }
}

四个概念足以读懂大多数 USD 工程：

概念含义工程直觉
Stage已组合、可查询的场景打开工程后看到的整体，而不只是某个源文件
Prim场景中的节点机器人、关节、相机和灯光都是 Prim
AttributePrim 的属性位置、质量等；许多属性支持按时间采样
Layer 与组合把多层描述合成为最终场景布局、材质和光照可以分层编辑，不必复制整份资产

references 引用外部资产，payload 标记可延迟加载的引用内容，variants 在同一资产中切换配置，sublayers 叠加场景层。Payload 并不会自动让某张 4K 纹理独立按需加载；实际加载行为仍取决于资产组织和运行时。

扩展名本质常见用途
.usdaASCII 文本阅读、审查和小场景
.usdcCrate 二进制较大资产与高效读取
.usd通用后缀，内容可为文本或二进制通用场景文件
.usdz符合 USDZ 约束的打包归档把场景及依赖作为一个包分发

URDF 导入 USD 不是换后缀。导入器会根据 URDF 生成一棵带 USD Physics 等属性的 Prim 树，但关节轴、坐标原点、限位、惯量、碰撞几何、单位和资源路径仍需复核。ROS 中使用的 URDF 与 Isaac 中使用的 USD 可以来自同一来源模型，却不能未经验收就假设动力学和几何完全一致。

USD 也不替代所有地图格式。Nav2 常见二维地图仍是 PGM 图像加 YAML 元数据；点云常用 PCD/PLY；3DGS 的 PLY 通常保存位置、缩放、旋转、不透明度和球谐系数等属性，而不是简单给每点写一组普通网格坐标。

4. ROS 2 与 rosbag：保存运行过程

静态模型跑起来以后，关节状态、坐标变换和传感器数据会持续流动。ROS 2 Topic 是在线消息通道，rosbag2 则把选中的消息及元数据记录下来，供回放、排障和离线处理。

常见 Topic消息类型内容
/joint_statessensor_msgs/msg/JointState关节位置、速度、力矩等字段
/tf、/tf_statictf2_msgs/msg/TFMessage动态与静态坐标变换
/camera/image_rawsensor_msgs/msg/Image相机图像及消息时间戳
/camera/pointssensor_msgs/msg/PointCloud2点云及字段布局
/odomnav_msgs/msg/Odometry里程计位姿、速度与协方差

robot_state_publisher 的常见职责就是使用 URDF 的静态结构和关节状态发布 TF。于是 URDF 描述身体，joint states 描述当前姿态，TF 把坐标关系提供给其他模块。

以 MCAP 存储为例，一个 bag 目录可能长这样：

my_grasp_bag/
├── metadata.yaml
└── my_grasp_bag_0.mcap

下面是 metadata 的结构示意，省略了其他字段与 Topic；时长使用整数纳秒，不是带单位的十进制字符串：

rosbag2_bagfile_information:
  duration:
    nanoseconds: 126500000000
  message_count: 38412
  topics_with_message_count:
    - topic_metadata:
        name: /joint_states
        type: sensor_msgs/msg/JointState
      message_count: 12650
ros2 bag record -a
ros2 bag record /joint_states /tf /wrist_cam/image_raw
ros2 bag play my_grasp_bag --rate 0.5
ros2 bag info my_grasp_bag

MCAP 是日志容器，不替你做训练对齐。它保存带时间戳的预序列化消息和模式信息。记录时间、主机接收时间与传感器曝光时间可能不同；要从日志生成训练数据，必须先理解这些时间戳的语义。

5. 训练数据集：把经历整理成样本

rosbag 更接近完整运行记录，训练数据集则需要明确的 episode、观测、动作、任务与统计信息。转换的关键不是把 .mcap 改名为 .parquet，而是建立每一步之间的语义对应。

格式典型结构适合与限制
LeRobotParquet 数值数据 + 视频 + 元数据面向机器人学习与 Hugging Face 生态；字段和目录需匹配所用版本
RLDSEpisode 包含 Step 序列适合序列决策与跨数据集复用；OXE 等数据集可使用这一表示
HDF5单文件中的层级数据集robomimic 等项目常用；HDF5 本身不规定统一的机器人字段约定

LeRobot v2 系列的一种典型目录如下：

g2_tray_dataset/
├── meta/
│   ├── info.json
│   ├── stats.json
│   ├── episodes.jsonl
│   └── tasks.jsonl
├── data/chunk-000/
│   └── episode_000000.parquet
└── videos/chunk-000/
    └── observation.images.wrist/
        └── episode_000000.mp4

info.json 描述字段，stats.json 保存归一化等统计，episodes 与 tasks 记录轨迹和任务元数据。视频压缩通常减少图像存储，但节省比例取决于分辨率、编码和内容，不能预设固定百分比。

{
  "observation.images.wrist": {
    "dtype": "video",
    "shape": [480, 640, 3]
  },
  "observation.state": {
    "dtype": "float32",
    "shape": [14]
  },
  "action": {
    "dtype": "float32",
    "shape": [14]
  }
}

读取 Hub 数据集的示例：

from lerobot.datasets.lerobot_dataset import LeRobotDataset

ds = LeRobotDataset("your_org/g2_tray")
sample = ds[0]

真正需要检查的是：observation.state 的关节顺序是否与机器人一致，图像和状态是否属于同一采集时刻，action[t] 是相对动作还是绝对目标，以及它与哪一帧后续观测对应。

6. 串起来：一台机器人的数据闭环

URDF / Xacro：本体结构
　↓ 导入、转换并验收
USD / MJCF 等：仿真场景与控制对象
　↓ 仿真运行，或真机运行
ROS 2 消息 → rosbag2 / MCAP：运行记录
　↓ 时间对齐、字段抽取、质量控制与版本化
LeRobot / RLDS / HDF5：训练数据集
　↓ 训练与闭环评测
策略部署 → 产生新的运行记录

这条链不是唯一流程。仿真器可以绕过 rosbag 直接写训练集，已有数据也可以先转成 RLDS 再进入训练。图的重点是：每次跨越容器时，都要保留坐标、时间、字段和版本的含义。

例如 AprilTag 位姿可以留在 rosbag 里供复盘，但只有把相机外参、关节状态、图像时刻和动作目标对应起来，它才可能成为可信的训练样本。

7. 格式转换之后，验收什么

检查项要回答的问题常见错误
结构link、joint、episode 和字段是否完整？静默丢关节、闭链被错误展开、回合边界错位
几何单位、坐标轴、父子关系和资源路径是否一致？毫米当米、网格原点漂移、碰撞模型没有随外观更新
时间时间戳来自曝光、采集还是主机接收？用到达时间替代曝光时间，把不同步的图像和状态配成一对
动作语义动作是绝对目标、增量还是速度？作用于哪个状态？把下一时刻目标当当前观测，或把相对量当绝对角
统计与版本归一化统计从哪批数据计算，配置是否可追溯？训练与推理使用不同统计，验证集信息泄漏进训练统计
回放证据转换前后能否逐帧、逐关节对照？只看文件能打开，不看实际轨迹与图像是否一致

最小验收流程可以是：固定一小袋输入 → 自动转换 → 校验字段、形状与时间 → 随机抽样回放 → 对照原始轨迹 → 保存转换器版本和校验值。文件格式只保证容器可读，不保证内容正确。

8. 速查：我要做什么，该用什么

需求常见选择别忘了
在 ROS 中描述机器人结构与坐标链URDF + Xacro关节轴、原点、限位、碰撞与惯量
在 MuJoCo 中建模与训练MJCF，或由其他模型转换转换后的动力学和接触行为
组织 Isaac Sim / Omniverse 场景USD / USDZ组合层、资产依赖和物理 schema
记录并回放 ROS 2 运行数据rosbag2 + MCAPTopic 类型、时间戳与采集配置
训练 VLA 或模仿学习策略LeRobot、RLDS 或项目既定 HDF5 schema观测动作对齐、版本与归一化统计
构建 Nav2 二维地图PGM + YAML分辨率、原点、占据阈值和坐标系

一句话总结：URDF 说「身体怎样连接」，USD 说「场景怎样组成」，rosbag 说「运行中发生了什么」，训练数据集说「哪些经历可以拿来学习」。格式转换的终点不是文件生成，而是语义经过验证。
